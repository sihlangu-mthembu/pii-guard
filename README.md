# pii-guard

A small Python tool that finds and redacts personal information (PII) in text and CSV files, **measures how well it does**, and produces the review material a data-privacy QA process needs: a residual-risk scan and a random spot-check sample.

It is tuned for South African data: it validates SA ID numbers (birth date plus Luhn check digit) and recognises local and +27 phone formats.

## What it detects

| Type | Rule |
| --- | --- |
| `SA_ID` | 13 digits with a real YYMMDD birth date **and** a valid Luhn check digit, so random 13-digit invoice numbers are not flagged |
| `CARD` | 15 or 16 digits (spaces or dashes allowed) with a valid Luhn check digit |
| `PHONE` | `0` or `+27`, then 9 digits, e.g. `082 555 1234`, `0825551234`, `+27 82 555 1234` |
| `EMAIL` | Standard email addresses |
| `NAME` | Names from a supplied list (whole words, case-sensitive) |

Each item is replaced with a placeholder, e.g. `Lerato: lerato@example.org` becomes `[NAME]: [EMAIL]`.

## Quick start

Needs Python 3.10 or newer. No packages to install.

```bash
python evaluate.py                 # precision and recall on 29 labelled test sentences
python run.py                      # redact data/tickets.csv, scan for leftovers, draw a spot-check sample
python -m unittest discover tests  # run the tests
```

## Results on the bundled test set

**Precision 96%, recall 92%** on 29 labelled sentences (24 found, 1 false alarm, 2 missed). Every error is listed in [`reports/evaluation.md`](reports/evaluation.md):

- **False alarm:** "Grace" in *"Grace Period Notice"* was redacted as a name.
- **Missed:** a name not on the list ("Mandla"), and a phone number with unusual spacing (`072 1234 567`).

The test set deliberately includes traps that must **not** be flagged (13- and 16-digit reference numbers that fail the checksum, money amounts, dates, a lowercase "grace period") and cases the rules are expected to miss, so the recall figure is honest rather than flattering.

For redaction, **recall matters more than precision**: a missed ID number is a privacy breach, while a false alarm is just one over-redacted word.

## Redaction run

`run.py` redacts the 50 synthetic support tickets (132 items) and then:

- **Scans for residual risk:** any row that still contains a long run of digits or an `@` is listed in `reports/redaction_summary.md` for a human to check. In the sample, 19 rows are flagged, all of them order references that correctly failed the ID checksum. That is exactly the kind of thing a reviewer must confirm, not assume.
- **Draws a spot-check sample:** 10 random redacted rows go to `reports/spot_check.csv`, with columns for a reviewer to mark each row OK or not.

## Using your own data

```bash
python run.py --input my_file.csv --column message_text --sample 20
```

To recognise more names, extend `DEFAULT_NAMES` in `pii_guard.py` or pass your own list to `redact()`.

## About the sample data

All data is **synthetic**, generated by `generate_sample_data.py` with a fixed seed. Emails use the reserved `example.com` and `example.org` domains. ID, card and phone numbers are random numbers built to pass the format checks; any match with a real person's number is coincidental.

## Limitations

- Name detection is list-based. Real deployments would add a named-entity recognition model to catch names that aren't on a list.
- Addresses, bank account numbers and passport numbers are not detected.
- Placeholders remove the value but keep the context; free text can still identify someone indirectly ("the only doctor in Hermanus").
- This is a learning project, not a compliance tool. It is no substitute for a POPIA or GDPR review.

## Project structure

```
pii-guard/
├── pii_guard.py              # detectors, Luhn and ID checks, redaction, residual scan
├── evaluate.py               # precision and recall on labelled test cases
├── run.py                    # redacts a CSV, writes summary and spot-check sample

├── output/                   # tickets_redacted.csv

```
